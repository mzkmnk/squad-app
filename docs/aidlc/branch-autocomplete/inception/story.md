# User Story: ブランチ選択オートコンプリート

## ユーザーストーリー（EARS形式）

### US1: ブランチのフィルタリング選択

**WHEN** ユーザーが Workspace 作成フォームでリポジトリを選択した時
**THEN** システムはブランチ入力欄を表示し、ユーザーが文字を入力すると部分一致するリモートブランチ候補をリスト表示する

### US2: 候補からのブランチ選択

**WHEN** ユーザーがオートコンプリート候補リストからブランチを選択した時
**THEN** システムは入力欄にそのブランチ名を設定し、候補リストを閉じる

### US3: 新規ブランチ作成ダイアログの表示

**WHEN** ユーザーがブランチ入力欄の横にある「新規作成」ボタンをクリックした時
**THEN** システムは新規ブランチ作成ダイアログを表示する。ダイアログには起点ブランチの選択欄と新規ブランチ名の入力欄が含まれる

### US4: 起点ブランチの選択

**WHEN** ユーザーが新規ブランチ作成ダイアログで起点ブランチ入力欄に文字を入力した時
**THEN** システムは部分一致するリモートブランチ候補をリスト表示し、選択できるようにする（ブランチ選択と同じオートコンプリート UI）

### US5: 新規ブランチの作成確定

**WHEN** ユーザーが新規ブランチ作成ダイアログで起点ブランチを選択し、有効なブランチ名を入力して確定した時
**THEN** システムはダイアログを閉じ、ブランチ入力欄に新規ブランチ名を設定し、新規作成対象としてマークする

## 受入条件（Given-When-Then形式）

### AC1: 部分一致フィルタリング

- **Given** リポジトリに `main`, `develop`, `feature/login`, `feature/payment`, `hotfix/urgent` のリモートブランチが存在する
- **When** ユーザーがブランチ入力欄に `feat` と入力する
- **Then** `feature/login` と `feature/payment` が候補として表示される

### AC2: 大文字小文字を区別しないフィルタリング

- **Given** リポジトリに `Feature/Login` ブランチが存在する
- **When** ユーザーが `feature` と入力する
- **Then** `Feature/Login` が候補として表示される

### AC3: 空入力時の全候補表示

- **Given** リポジトリにリモートブランチが存在する
- **When** ユーザーがブランチ入力欄にフォーカスし、何も入力していない（または入力を全削除した）
- **Then** 全てのリモートブランチが候補として表示される

### AC4: 候補選択によるブランチ確定

- **Given** ブランチ候補リストが表示されている
- **When** ユーザーが候補の `feature/login` をクリックする
- **Then** 入力欄に `feature/login` が設定され、候補リストが閉じる

### AC5: キーボード操作

- **Given** ブランチ候補リストが表示されている
- **When** ユーザーが上下矢印キーで候補を移動し、Enter キーで選択する
- **Then** 選択された候補が入力欄に設定され、候補リストが閉じる

### AC6: Escape キーによる候補リスト閉じ

- **Given** ブランチ候補リストが表示されている
- **When** ユーザーが Escape キーを押す
- **Then** 候補リストが閉じ、入力欄の値は変更されない

### AC7: 新規作成ボタンの表示

- **Given** リポジトリが選択されており、ブランチ一覧の取得が完了している
- **When** ブランチ入力欄が表示される
- **Then** 入力欄の横に「新規作成」ボタンが表示される

### AC8: 新規ブランチ作成ダイアログの構成

- **Given** ユーザーが「新規作成」ボタンをクリックした
- **When** ダイアログが表示される
- **Then** ダイアログには上から順に「起点ブランチ」入力欄（オートコンプリート）と「新規ブランチ名」入力欄が表示される

### AC9: 起点ブランチのデフォルト選択

- **Given** リポジトリに `main`, `develop`, `feature/login` のリモートブランチが存在する
- **When** 新規ブランチ作成ダイアログが開かれる
- **Then** 起点ブランチの入力欄にはデフォルトブランチ（例: `main`）が初期設定されている

### AC9-2: 起点ブランチのフィルタリング

- **Given** 新規ブランチ作成ダイアログが表示されている
- **When** ユーザーが起点ブランチ入力欄に `dev` と入力する
- **Then** `develop` が候補として表示される（ブランチ選択と同じオートコンプリート動作）

### AC10: 新規ブランチ名のバリデーション — 有効

- **Given** 新規ブランチ作成ダイアログが表示されている
- **When** ユーザーが `feature/new-api` と入力する
- **Then** バリデーションエラーは表示されず、作成ボタンが有効になる

### AC11: 新規ブランチ名のバリデーション — 無効

- **Given** 新規ブランチ作成ダイアログが表示されている
- **When** ユーザーが `feature/..invalid` と入力する
- **Then** Git の命名規則に違反している旨のバリデーションエラーが表示され、作成ボタンが無効になる

### AC12: 新規ブランチ名の重複チェック

- **Given** リポジトリに `feature/login` ブランチが既に存在する
- **When** ユーザーが新規ブランチ名に `feature/login` と入力する
- **Then** 「同名のブランチが既に存在します」というエラーが表示され、作成ボタンが無効になる

### AC13: 新規ブランチ作成の確定

- **Given** 起点ブランチに `develop` を選択し、新規ブランチ名に `feature/new-api` を入力した
- **When** ユーザーがダイアログの作成ボタンをクリックする
- **Then** ダイアログが閉じ、ブランチ入力欄に `feature/new-api` が設定される

### AC14: 新規ブランチ作成のキャンセル

- **Given** 新規ブランチ作成ダイアログが表示されている
- **When** ユーザーがキャンセルボタンをクリックする
- **Then** ダイアログが閉じ、ブランチ入力欄の値は変更されない

### AC15: Workspace 作成時の新規ブランチ

- **Given** ユーザーがリポジトリ A で新規ブランチ `feature/new-api`（起点: `develop`）を設定し、Workspace 作成ボタンを押した
- **When** Workspace 作成処理が実行される
- **Then** リポジトリ A に対して `develop` を起点に `feature/new-api` ブランチが worktree 作成時に新規作成される

## 非機能要件

### パフォーマンス

- フィルタリングは入力ごとにリアルタイムで行い、体感遅延なく候補を更新する（クライアントサイドフィルタリング）
- ブランチ数が 1000 件を超えるリポジトリでも候補リストの表示がスムーズであること

### セキュリティ

- ブランチ名入力値は既存の `validateBranchName` でサニタイズし、Git コマンドインジェクションを防止する

### アクセシビリティ

- オートコンプリートは `role="combobox"` + `role="listbox"` パターンに準拠する
- キーボードのみで全操作が完結すること（矢印キー、Enter、Escape）
- スクリーンリーダーで候補数と選択状態が読み上げられること
- 新規ブランチ作成ダイアログはフォーカストラップを実装すること
