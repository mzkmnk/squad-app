# AI-DLC Construction: Code Generation（常に実行、Unit 単位）

## 2パート構成

### Part 1 - Planning

1. 要件・設計成果物を分析
2. 詳細なコード生成計画を作成（チェックボックス付き）
3. 各ステップにストーリーのトレーサビリティを含める
4. 計画をユーザーに提示し承認を得る

### Part 2 - Generation

1. 承認された計画を順番に実行
2. 完了したステップは即座に `[x]` に更新
3. コード、テスト、成果物を生成

## Critical Rules

- **ハードコードロジック禁止**: 計画に書かれたことのみ実行
- **計画順序の厳守**: ステップ順序からの逸脱禁止
- **チェックボックス即時更新**: 作業完了と同じインタラクションで更新
- **brownfield ではファイル複製禁止**: 既存ファイルを直接修正

## TDD アプローチ（本プロジェクト独自の強化）

公式 AI-DLC にはないが、本プロジェクトでは TDD を採用:

1. テストコードを先に作成
2. テストをパスさせる実装コードを作成
3. リファクタリング

## 成果物

- `docs/aidlc/{feature_name}/construction/{unit_name}/plan.md` — コード生成計画
- 実際のソースコード（ワークスペースルートに配置）

## 計画テンプレート

```markdown
# Code Generation Plan: [unit_name]

## 概要

[この Unit で生成するコードの概要]

## 実装タスク

### 1. [ステップ名]

- [ ] [タスク1: 具体的な実装内容]
- [ ] [タスク2: 具体的な実装内容]
- [ ] テスト: [対応するテストケース]

### 2. [ステップ名]

- [ ] [タスク1: 具体的な実装内容]
- [ ] [タスク2: 具体的な実装内容]
- [ ] テスト: [対応するテストケース]

### 3. 最終確認

- [ ] 全テスト実行・パス確認（`pnpm test`）
- [ ] lint 確認（`pnpm lint`）
- [ ] ビルド確認（`pnpm build`）

## ストーリートレーサビリティ

| タスク    | ストーリー | 受入条件 |
| --------- | ---------- | -------- |
| [タスク1] | US1        | AC1      |
```

## 承認

2択の完了メッセージを提示:

- 🔧 **変更を依頼**
- ✅ **承認して次のステージへ**
